## NEW: ISS-024 [medium] — plan deliberation can never agree
`computeAgreement` (src/backends/deliberation.ts) keys matching on non-null file+line; plan findings have neither, so **every** plan finding routes to `keyless` → divergent. Live proof: deliberate-deep plan review of a draft ISS-022 fix plan returned **0 agreed / 11 divergent** even though both providers flagged the same three concerns (mtime granularity, composite-rebuild lifecycle, failure-policy gaps) in near-identical words. Fix needs a plan-specific match key (normalized category + text similarity, or provider-emitted topic tags), ideally data-driven like T-029 was. This is the natural next quality ticket.

## Bonus: free design review of ISS-022 (config reload plan)
The plan probe doubled as a real review of a draft ISS-022 approach (per-call config reload, mtime cache). Both providers said **revise**; cross-confirmed concerns: rebuilding the backend composite mid-session (in-flight reviews / resource lifecycle undefined), mtime 1s-granularity + same-mtime edits, failure policy only covers invalid JSON (not missing/unreadable/validation-fail), runtime-reloadable `codex_path` is a security surface, "effective config" equality undefined, no test strategy. Full JSON at scratchpad probe/plan-stdout.json (session-scoped — the substance is captured here). Whoever picks up ISS-022 should treat these as plan requirements.
